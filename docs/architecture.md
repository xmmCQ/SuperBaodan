# 应用结构

运行入口：`npm start` → `app/main/main.mjs`。

| 目录 | 职责 |
|---|---|
| `app/main` | Electron 生命周期、窗口、托盘、原生文件操作、资源协议、服务进程管理 |
| `app/preload` | 隔离界面与主进程，暴露受限调用和事件订阅 |
| `app/renderer` | 日历、助手和设置界面，不访问 Node.js、不持有文件系统权限 |
| `app/services` | 独立 Node 服务进程；`commands` 编排业务操作，`domain` 实现业务规则 |
| `app/shared` | 命令清单、跨进程错误和共用数据校验，不依赖 Electron 或界面 |
| `scripts`、`extras` | Windows 软件启动支持和模型工具扩展 |
| `test` | 单元、跨进程、权限、界面及业务回归测试 |

## 通信边界

- 界面资源由 `app://workbench/` 协议加载，不创建本地 HTTP 监听端口。
- 界面通过 `workbench.invoke(id, name, args)` 调用命名操作，例如 `records.create`、`files.upload`；不传递 HTTP 路由或方法。
- 主进程检查发送窗口、顶层框架、命令白名单、参数大小及退出状态，再通过受控子进程句柄转发请求。
- 每轮服务进程拥有独立运行标识；请求带唯一 ID，迟到结果不能完成新实例的请求。
- 模型及登录事件经 IPC 传递。事件队列有界，积压时提示重新同步快照。
- 文件选择和文档打开由主进程调用 Electron 原生接口；文档路径先由业务层检查登记记录和版本。
- 二进制预览使用受工作区校验的 `app://workbench/content` 资源，不暴露任意 `file://` 路径。
- 模型请求、在线节假日、Skill 获取和 OAuth 回调属于业务所需外部网络通信，不是应用 Web 入口。

## 生命周期

关闭窗口只隐藏；托盘退出进入唯一静默清理流程。退出期间禁止新请求，等待已接受操作和资源清理，超时只终止本轮创建的服务进程。不按端口、进程名或后代树终止程序。

## 验证

- `npm test`：全量回归。
- `npm run test:smoke`：跨进程 IPC、权限、资源隔离和主要界面链路。
- 浏览器自动化仅用于无模型界面夹具。`test/helpers` 中的 HTTP 适配器属于测试工具，不由产品入口引用，也不进入运行时通信链路。
- 模型账号、外部办公软件及真实系统关机需要单独人工验收。
