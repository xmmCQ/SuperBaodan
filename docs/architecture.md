# 应用结构

入口：`npm start` → `app/main/main.mjs`。Electron 主进程直接创建并监管两个业务子进程；Agent 不是本地服务的孙进程。

## 职责与命令归属

| 进程 | 职责 / 命令 |
| --- | --- |
| Electron 主进程 | 窗口、托盘、受控 IPC、资源协议、原生对话框、进程监管；执行业务层已校验的外部文件/软件启动 |
| 本地业务进程 `app/services/main.mjs` | `tasks.*`、`records.*`、`vskills.*`、`documents.*`、`apps.*` 配置与校验、`holidays.*`、`files.*`、`system.status`、工作区登记、会话元数据/全文搜索、项目提示词普通读取 |
| Agent 进程 `app/agent/main.mjs` | `PiSdkRuntime`、`PiAdmin`、`ModelCatalog`、`SkillManager`、SDK 模型/设置/会话对象；`auth.*`、`models.*`、`skills.*`、会话运行和修改、提示词保存＋重载、工具状态、`PromptReceipts`、`UiEventPayloads` |
| 本地协调 | Agent 启动和初始化描述、bootstrap 组合、最后使用会话登记、工作区两阶段切换、Agent 事件筛选 |

本地 `vskills.*` 是快捷提示，不是 Pi 技能。Pi 源文件部分仍保留在 `app/services/domain`，但只由 Agent 入口加载和实例化。主进程、本地进程不构造 SDK 运行时，不创建远程 `.host.session` 仿真对象。

## 通信与就绪

- 前端接口继续是 `workbench.invoke(id, name, args)`，资源仍为 `app://workbench/`，没有产品 HTTP 服务或新监听端口。
- 路径：渲染器 → 主进程 → 本地业务；Agent 请求再异步经过主进程转发给 Agent。
- 本地业务就绪即可显示首页；助手自动预热但不阻塞首页。
- 子进程先发 `hello`，建立监管后主进程发 `boot`。Agent 的 `ready` 只表示通信就绪；SDK 初始化和扩展交互随后进行。
- `system.status` 和 `agent.connect` 使用已发布的状态，不为状态查询等待 SDK。
- 协议版本为1，按请求 ID、运行 ID及适用的工作区 epoch、会话代次隔离。内部命令白名单独立于前端白名单。
- 全局上限128，普通 Agent 请求最多96；保留控制消息容量，取消/交互响应不等待普通业务队列。事件背压及大 UI 按需取回保留。
- 未确认的提交返回断开/结果未知；回执查询不会执行原请求，新进程不重发旧提示或配置写入。

## 工作区与存储

本地进程独占工作区登记及最后会话记录。Agent 以操作 ID 执行准备、确认或回滚；本地只在目标已准备后写入登记。响应丢失时查询操作状态，不盲目重复切换；无法确认则暂停助手，等待明确重试。回滚使用新的 epoch。

BaodanPark 路径不变。注册/普通读取仅检查已有目录与路径，Agent 独占管理目录准备和资源写入，不把进程内 Map 当作跨进程锁。首次资源尚未准备时普通提示词读取返回不存在；保存前仍须通过版本校验。

工具调用及已确认文件状态由 Agent 持有，本地仅转发序列化结果。会话变化通过事件使本地元数据扫描缓存失效。

## 崩溃与退出

Agent 崩溃只使助手不可用，本地业务继续。界面有“重试助手”；确认旧实例退出后才创建新实例，不循环重启、不续跑旧提示。工作区登记已提交后发生断连，恢复依据已登记工作区。

关闭窗口隐藏到托盘；托盘退出与受控退出入口共用 `requestExit`，无确认、不自动保存草稿。退出并行停止两个业务进程，共用约10秒正常预算；各自排空已受理写入，不串行等待两个10秒。

Windows 使用各自独立的原生 Job Object。短时系统 PowerShell 建立作业并把句柄交给 Electron；不存在常驻 PowerShell 守护进程。主进程硬退出时由操作系统回收业务进程和其受管子进程；Agent 根进程异常退出后清理其工具子进程。仅按本轮句柄/运行标识处理，不按进程名批量结束。用户主动打开的办公软件由主进程原生启动，避免被业务进程作业误杀。

开发版沿用 SDK 路径解析；正式版使用显式内置路径配置，未配置时按应用内依赖路径解析，不落到开发环境的全局 Pi 路径。正式安装包本轮未生成或验证。

## 本轮验收（按更新后的最小要求）

已完成的旧版验收结果直接复用，没有重复运行新的合并用例：

- 假 Agent **同步阻塞5秒**时，本地 `tasks.day`、`tasks.dashboard`、`records.list`、`system.status` 均在阻塞解除前返回，实测约0.4～1.9ms；Agent结束后本地CRUD仍可用。
- 容量隔离、显式重试、不自动重发、启动交互/大 UI、工作区成功及失败恢复、模拟登录取消/输入、模型偏好、技能接口、提示词保存重载，已用隔离数据和假供应商验证。
- Windows 作业监管已验证 Agent/自有工具清理，以及监管父进程在阻塞、Local启动、Agent启动时硬退出的回收。

**按新版补做一次真实 Electron 冒烟：**启动 → 立即切日期 → 助手就绪 → 切换一次工作区 → 共用托盘退出链。首次切日 **28.3ms**（隔离数据、单次记录，不设置机器敏感门槛）；两个业务进程直属 Electron，退出后均已回收。退出由与托盘菜单相同的受控入口触发，未模拟点击系统托盘菜单。

迁移后仅按名称补跑11项直接受影响的现有关键用例，覆盖未退出不重复启动、取消/断开、启动交互、已受理写入排空、工具确认、旧工作区快照和维护闸门，均通过。其余旧测试仅适配接口，未整套重跑。

主进程和本地服务的静态依赖检查未发现 SDK 运行时、模型管理器、技能管理器或 SDK loader 依赖。没有进行真实账号登录、付费对话、技能安装或真实用户数据启动验收。

## 运行测试

日常仅选受影响项，不顺带全量或视觉验收。新版最小用例保留为：

```sh
node --test --test-name-pattern="最小隔离" test/agent-process.test.mjs
node --test test/desktop-agent-smoke.test.mjs
```

已有覆盖证据时不重复执行。`npm test` 仍只运行单元层；其他分层入口见 `docs/testing.md`。
